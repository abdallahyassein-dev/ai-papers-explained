## 1. Executive Summary & Motivation

**Faster R-CNN** represents the crowning achievement of the two-stage object detection paradigm. 

Prior to Faster R-CNN:
- **R-CNN (2014)** was crippled by high inference latency (**~47 seconds per image**) because it forwarded ~2,000 warped image crops through AlexNet independently.
- **Fast R-CNN (2015)** solved the feature recomputation problem by running the deep convolutional layers once over the full image and using **Region of Interest (RoI) Pooling**, dropping the CNN inference time to **~0.32 seconds**.
- **However**, Fast R-CNN still relied on external, CPU-bound region proposal algorithms (specifically **Selective Search**), which required **~2.0 seconds per image**.

Thus, the region proposal step became the absolute **computational bottleneck**, accounting for over **85% of total test-time latency**!

```
Total Inference Time in Fast R-CNN:
┌─────────────────────────────────────────────────────────────┬────────┐
│ Selective Search on CPU (2.000s)                            │ CNN    │
│ [==========================================================]│ (0.3s) │
└─────────────────────────────────────────────────────────────┴────────┘
 ◄───────────────────────── ~2.3 seconds ─────────────────────────────►
```

### The Central Question of the Paper:
> *"Can region proposals be generated by a deep neural network that shares convolutional features with the detection network at virtually zero additional marginal cost?"*

### The Breakthrough Solution:
Faster R-CNN introduces the **Region Proposal Network (RPN)**:
1. **Fully Convolutional Network (FCN)** that slides over the last shared convolutional feature map.
2. Directly outputs object bounds and objectness scores at each location.
3. Introduces **Anchor Boxes** (multi-scale and multi-aspect reference boxes) to eliminate the need for costly image/filter pyramids.
4. Operates in just **10 milliseconds** on the GPU!
5. Pushes the entire object detection pipeline to **near real-time (5 to 17 fps)** while establishing state-of-the-art accuracy on PASCAL VOC and MS COCO.

## 3. The Proposal Bottleneck: Why Fast R-CNN Was Not Fast Enough

In Fast R-CNN, the detection network operates on high-end GPUs. But where do the candidate boxes come from?
- **Selective Search (SS):** A CPU-based heuristic that overseats an image into superpixels based on color/texture/size similarity and iteratively groups them via hierarchical clustering. It takes **~2.0 seconds** on a modern CPU.
- **EdgeBoxes:** Another popular proposal algorithm based on edge density; it takes **~0.2 to 0.3 seconds**, but still requires separate CPU execution and cannot be trained end-to-end with the detection objective.

Because Fast R-CNN takes only ~0.3s for its CNN forward pass:
$$\text{Total Time} = 2.0\text{s (Selective Search)} + 0.3\text{s (CNN)} = 2.3\text{s}$$

Selective Search consumes **87% of the total runtime**. If you want a real-time object detector, you **cannot** rely on external CPU-based proposal generators. 

**Faster R-CNN's hypothesis:** The convolutional feature maps already contain rich semantic, hierarchical, and spatial information about where objects are. Why not attach a tiny, fast neural network on top of those features to predict candidate proposals directly on the GPU?

## 5. The Region Proposal Network (RPN) in Depth

### 5.1 Motivation & Design
An RPN takes as input a convolutional feature map of arbitrary size (output by the backbone, such as VGG-16 or ZF) and outputs a set of rectangular object proposals, each with an **objectness score**.

To build this network, a small sub-network is slid over the convolutional feature map:
- It processes an $n \times n$ spatial window (the paper uses $n = 3$, corresponding to a $3 \times 3$ convolution).
- Each sliding window is mapped to a lower-dimensional feature vector:
  - **256-d** for ZF Net.
  - **512-d** for VGG-16.
- This feature vector is fed into two sibling $1 \times 1$ convolutional layers:
  1. **`cls` layer (Classification):** Outputs $2k$ scores (probabilities of being an object vs. background for $k$ anchors).
  2. **`reg` layer (Regression):** Outputs $4k$ coordinates (parameterized coordinates for $k$ anchors).

```
                      Shared Feature Map (e.g. H x W x 512)
                                     │
                                     ▼
                          3x3 Convolution (512 filters)
                                     │
                                     ▼
                      Intermediate Feature Map (H x W x 512)
                                     │
                    ┌────────────────┴────────────────┐
                    │ (1x1 Conv)                      │ (1x1 Conv)
                    ▼                                 ▼
              `cls` layer                       `reg` layer
           (H x W x 2k scores)               (H x W x 4k deltas)
```

---

### 5.2 Sliding Window Mechanism
At each sliding window location on the convolutional feature map:
- The center of the $3 \times 3$ receptive field corresponds to a specific point on the original input image.
- Because of the backbone's stride (called the **feature stride**, typically $16$ in VGG-16):
  - Moving $1$ pixel on the feature map corresponds to moving $16$ pixels on the input image.
- At **each** sliding window location, we predict multiple region proposals simultaneously.
- The maximum number of possible proposals for each location is denoted by $k$.

---

### 5.3 Anchors: The Core Innovation
How can a single sliding point detect both a tiny bird and a giant bus?

Prior methods used one of two paradigms:
1. **Pyramids of images (Multi-scale images):** Resize the image to multiple resolutions and scan each resolution. This is computationally expensive.
2. **Pyramids of filters (Multi-scale filters):** Apply convolutional filters of various spatial sizes ($5 \times 5$, $7 \times 7$, $11 \times 11$) to the feature map.

Faster R-CNN introduces a third, dramatically superior paradigm: **Pyramids of Anchors (Reference Boxes)**.

> **Anchor Definition:**  
> An **anchor** is a predefined reference bounding box centered at the sliding window location. Each anchor is characterized by a specific **scale** and **aspect ratio**.

The authors choose:
- **3 Scales:** Areas of $128^2$, $256^2$, and $512^2$ pixels on the input image.
- **3 Aspect Ratios (width : height):** $1:1$, $1:2$, and $2:1$.

Combining 3 scales $\times$ 3 aspect ratios gives:
$$k = 3 \times 3 = 9 \text{ anchors per sliding position}$$

```
                Scale 1 (128^2)          Scale 2 (256^2)          Scale 3 (512^2)
           ┌───────────────────────┬────────────────────────┬────────────────────────┐
Aspect 1:1 │        ┌───┐          │        ┌─────┐         │       ┌─────────┐      │
           │        │   │          │        │     │         │       │         │      │
           │        └───┘          │        └─────┘         │       │         │      │
           │                       │                        │       └─────────┘      │
           ├───────────────────────┼────────────────────────┼────────────────────────┤
Aspect 1:2 │        ┌─┐            │        ┌──┐            │       ┌────┐           │
(tall)     │        │ │            │        │  │            │       │    │           │
           │        │ │            │        │  │            │       │    │           │
           │        └─┘            │        └──┘            │       │    │           │
           │                       │                        │       └────┘           │
           ├───────────────────────┼────────────────────────┼────────────────────────┤
Aspect 2:1 │        ┌──────┐       │        ┌─────────┐     │       ┌─────────────┐  │
(wide)     │        └──────┘       │        └─────────┘     │       │             │  │
           │                       │                        │       └─────────────┘  │
           └───────────────────────┴────────────────────────┴────────────────────────┘
```

For a convolutional feature map of size $W \times H$ (e.g., $60 \times 40$):
$$\text{Total Anchors} = W \times H \times k = 60 \times 40 \times 9 = 21,600 \text{ anchors!}$$

---

### 5.4 Multi-Scale & Multi-Aspect Handling
Because the anchors already span 3 diverse scales and 3 aspect ratios:
- All features are computed from a **single-scale image**.
- All features are extracted using a **single-size convolutional filter** ($3 \times 3$).
- The network simply learns to classify and adjust the anchors!
- This completely avoids the memory and compute overhead of image pyramids.

---

### 5.5 Translation Invariance Property
A standout mathematical property of the Anchor-based RPN is **Translation Invariance**:
- If an object in an image shifts horizontally or vertically, its proposal should shift by the exact same amount, and the same function should be capable of predicting the proposal in either location.
- In RPN, because the sliding window and anchor generation are convolutional operations, the representations and predictions are inherently translation-invariant.
- By contrast, competing deep proposal methods at the time (like **MultiBox**, Erhan et al., 2014) used fully-connected layers to output coordinates for the entire image, which was **not** translation invariant: if an object translated, MultiBox could fail completely.
- Translation invariance also drastically **reduces parameter count**:
  - MultiBox output layer had millions of parameters.
  - Faster R-CNN's RPN output layer has:
    - $512 \times (2 \times 9) = 9,216$ weights for `cls`.
    - $512 \times (4 \times 9) = 18,432$ weights for `reg`.
  - Minimal parameter count minimizes the risk of overfitting on smaller datasets like PASCAL VOC.

## 6. RPN Training & Objective Formulation

### 6.1 Positive vs. Negative Anchor Assignment
To train the RPN, each of the thousands of anchors must be assigned a binary class label: **Object (Positive = 1)** or **Background (Negative = 0)**.

Assignment rules based on **Intersection over Union (IoU)** with ground-truth bounding boxes:

1. **Positive Label ($p^* = 1$):**
   - **Rule A (Best Match):** The anchor(s) with the highest IoU overlap with a given ground-truth box. *(This ensures every ground-truth box has at least one matching positive anchor, even if its IoU is below 0.7!)*
   - **Rule B (High Overlap):** Any anchor that has an $\text{IoU} \ge 0.7$ with any ground-truth box.

2. **Negative Label ($p^* = 0$):**
   - Any non-positive anchor whose $\text{IoU} < 0.3$ with **all** ground-truth boxes.

3. **Neutral / Ignored Anchors:**
   - Anchors that have $0.3 \le \text{IoU} < 0.7$.
   - These anchors are ambiguous (borderline overlap); they do **not** contribute to the training loss.

---

### 6.2 The Multi-Task Loss Function
The RPN objective minimizes a multi-task loss defined over an image:

$$L(\{p_i\}, \{t_i\}) = \frac{1}{N_{cls}} \sum_{i} L_{cls}(p_i, p_i^*) + \lambda \frac{1}{N_{reg}} \sum_{i} p_i^* L_{reg}(t_i, t_i^*)$$

Where:
- $i$ is the index of an anchor in a mini-batch.
- $p_i$ is the predicted probability that anchor $i$ is an object.
- $p_i^*$ is the ground-truth binary label ($1$ if positive, $0$ if negative).
- $t_i = (t_x, t_y, t_w, t_h)$ is a vector representing the 4 parameterized coordinates of the predicted bounding box.
- $t_i^*$ is the coordinate vector of the ground-truth box associated with positive anchor $i$.
- $L_{cls}$ is the **log loss** (binary cross-entropy) over two classes (object vs. not object):
  $$L_{cls}(p_i, p_i^*) = - \left[ p_i^* \log(p_i) + (1 - p_i^*) \log(1 - p_i) \right]$$
- $L_{reg}$ is the regression loss, active **only for positive anchors** due to the multiplication by $p_i^*$ ($p_i^* L_{reg} = 0$ when $p_i^* = 0$).
- $N_{cls}$ is the classification normalization term (mini-batch size = $256$).
- $N_{reg}$ is the regression normalization term (number of anchor locations $\approx 2,400$).
- $\lambda$ is a balancing hyperparameter. The paper sets $\lambda = 10$, making both loss terms roughly equally weighted.

---

### 6.3 Bounding Box Parameterization (Deltas)
The regression layer does not directly output raw pixel coordinates $(x, y, w, h)$. Instead, it outputs scale-invariant offsets and log-space size transformations relative to the anchor box:

Given:
- Anchor box: Center $(x_a, y_a)$, width $w_a$, height $h_a$.
- Ground-truth box: Center $(x^*, y^*)$, width $w^*$, height $h^*$.
- Predicted box: Center $(x, y)$, width $w$, height $h$.

The parameterized regression targets $t^* = (t_x^*, t_y^*, t_w^*, t_h^*)$ are computed as:

$$\begin{aligned}
t_x^* &= \frac{x^* - x_a}{w_a}, & \quad t_y^* &= \frac{y^* - y_a}{h_a} \\
t_w^* &= \ln\left(\frac{w^*}{w_a}\right), & \quad t_h^* &= \ln\left(\frac{h^*}{h_a}\right)
\end{aligned}$$

The model predicts $t = (t_x, t_y, t_w, t_h)$. At test time, the predicted bounding box is decoded as:

$$\begin{aligned}
x &= x_a + w_a \cdot t_x, & \quad y &= y_a + h_a \cdot t_y \\
w &= w_a \cdot \exp(t_w), & \quad h &= h_a \cdot \exp(t_h)
\end{aligned}$$

**Why this parameterization?**
1. Center shifts are normalized by anchor dimensions: a shift of 10 pixels matters a lot for a 20-pixel anchor, but very little for a 500-pixel anchor.
2. Width and height adjustments are in log-space: $\exp(t_w)$ is guaranteed to be strictly positive ($> 0$), preventing physically impossible negative widths or heights!

---

### 6.4 Smooth L1 Loss vs. L2 / L1 Loss
The regression loss function uses the **Smooth $L_1$ loss**:

$$L_{reg}(t_i, t_i^*) = \sum_{j \in \{x, y, w, h\}} \text{smooth}_{L_1}(t_{i, j} - t_{i, j}^*)$$

Where:
$$\text{smooth}_{L_1}(x) = \begin{cases} 
0.5 x^2 & \text{if } |x| < 1 \\ 
|x| - 0.5 & \text{otherwise} 
\end{cases}$$

```
Loss
 │                                           _ L2 Loss: x^2 (explodes on outliers!)
 │     \                                   / 
 │      \          _ - ~ - _              /   
 │       \     _ -           - _         /    
 │        \  -                   -      /     
 │         \                       -   /      
 │          \                     / - /       
 │           \                   /   -        
 │            \       _ _       /             
 │             \    /     \    /   ── Smooth L1: Quadratic near 0, Linear for |x| >= 1
 │              \  /       \  /    
 └───────────────\/─────────\/──────────────── Error (x)
                -1.0   0   1.0
```

#### Why Smooth L1?
- **L2 Loss ($x^2$):** When an initial bounding box has large error, the gradient $2x$ explodes, destabilizing training.
- **L1 Loss ($|x|$):** Its derivative is discontinuous at $x = 0$ ($\pm 1$), causing oscillations around the optimum.
- **Smooth L1:** Combines the best of both worlds:
  - For small errors ($|x| < 1$), it behaves like $L_2$ (smooth, continuous gradient $x \to 0$).
  - For large errors ($|x| \ge 1$), it behaves like $L_1$ (steady gradient $\pm 1$, robust against outliers).

---

### 6.5 Mini-Batch Sampling Strategy
Although an image generates $\approx 20,000$ anchors, calculating loss on all of them would heavily bias training toward negative samples (since background anchors vastly outnumber object anchors).

- Instead, each mini-batch is sampled from a **single image**.
- Exactly **256 anchors** are randomly chosen:
  - Up to **128 positive anchors**.
  - Remaining slots filled with **negative anchors** (to maintain a $1:1$ positive-to-negative ratio).
- If an image has fewer than 128 positive anchors, the remaining quota is padded with negative anchors.

## 7. Inference Pipeline & Proposal Generation

At test time, the RPN generates candidate proposals through the following steps:

```
Step 1: Input image passed through Conv Backbone ──► Feature Map (e.g. 50 x 38 x 512)
                                                             │
Step 2: 3x3 Conv + 1x1 Cls & Reg ──► 17,100 Anchor Predictions
                                                             │
Step 3: Bounding Box Decoding ──► Transform anchors by predicted (tx, ty, tw, th)
                                                             │
Step 4: Boundary Clipping ──► Clip boxes to image dimensions [0, W] and [0, H]
                                                             │
Step 5: Discard Small Boxes ──► Remove boxes smaller than min threshold (e.g. 16px)
                                                             │
Step 6: Rank by Score ──► Sort all proposals by positive `cls` probability
                                                             │
Step 7: Pre-NMS Top-K ──► Keep top 6,000 proposals (for speed)
                                                             │
Step 8: Non-Maximum Suppression (NMS) ──► Apply NMS with IoU threshold 0.7
                                                             │
Step 9: Post-NMS Top-N ──► Select top 300 proposals
                                                             │
Step 10: Deliver 300 Proposals to RoI Pooling in Fast R-CNN!
```

### 7.1 Anchor Transformation & Clipping
1. Many anchors extend beyond the image borders (e.g., an anchor of size $512 \times 512$ near an image edge). During training, cross-boundary anchors are ignored so they do not contribute to gradients.
2. At test time, cross-boundary anchors are projected and **clipped** to the image boundary edges.

### 7.2 Proposal Non-Maximum Suppression (NMS)
Because anchors heavily overlap with their spatial neighbors:
- The top-ranked anchors often correspond to the same underlying object.
- **NMS** is applied based on the `cls` scores with an IoU threshold of **0.7**.
- NMS leaves roughly **2,000 proposals per image during training**, and **300 proposals per image during testing**.
- Using only 300 proposals produces detection accuracy matching or exceeding Selective Search's 2,000 proposals!

## 8. Feature Sharing: Training RPN and Fast R-CNN Jointly

### 8.1 The Sharing Dilemma
Faster R-CNN contains two networks: RPN and Fast R-CNN.
- Both networks rely on convolutional layers (e.g., conv1 through conv5 of VGG-16).
- If trained independently, each network modifies its convolutional features in different ways, doubling the computation at test time.
- The goal is to make both networks **share the exact same convolutional weights**.

However, training them jointly is non-trivial because the RoI Pooling layer requires inputs (the proposals) that are themselves the output of RPN.

---

### 8.2 4-Step Alternating Training Algorithm
The authors developed an elegant **4-Step Alternating Training** scheme to share convolutional features:

```
[ Step 1: Train RPN ]
ImageNet Pre-trained ──► [Conv Layers (Trainable)] ──► [RPN Heads] (Trained via RPN Loss)
                                    │
                                    ▼ (Produces Initial Proposals)

[ Step 2: Train Fast R-CNN ]
ImageNet Pre-trained ──► [Conv Layers (Trainable)] ──► [RoI Pool (Step 1 Proposals)] ──► [Fast R-CNN Heads]
                         (Trained via Detection Loss; NO shared weights yet!)
                                    │
                                    ▼

[ Step 3: Fine-Tune RPN with Shared Features ]
Step 2 Fast R-CNN Weights ──► [Conv Layers (FROZEN ❄️)] ──► [RPN Heads (Fine-Tuned 🔥)]
                              (Only RPN unique layers update!)
                                    │
                                    ▼ (Produces Refined Proposals)

[ Step 4: Fine-Tune Fast R-CNN Heads ]
Step 3 Shared Conv Weights ──► [Conv Layers (FROZEN ❄️)] ──► [RoI Pool (Step 3 Proposals)] ──► [Fast R-CNN Heads (Fine-Tuned 🔥)]
                               (Only Fast R-CNN fc layers update!)
                                    │
                                    ▼
                 Unified Network with Shared Convolutional Features!
```

1. **Step 1: Train RPN:** Initialized with ImageNet pre-trained weights, fine-tuned end-to-end for the region proposal task.
2. **Step 2: Train Fast R-CNN:** Initialized with ImageNet pre-trained weights. Uses the proposals generated by Step 1 RPN. At this point, the two networks do not share conv layers.
3. **Step 3: Re-initialize RPN with detector conv layers:** Initialize RPN with the conv layers from Step 2, but **freeze the shared conv layers** and only fine-tune the layers unique to RPN.
4. **Step 4: Fine-tune Fast R-CNN:** Keeping the shared conv layers **frozen**, fine-tune only the unique layers of Fast R-CNN (fc6, fc7, cls, reg) using proposals from Step 3.

---

### 8.3 Approximate Joint Training & End-to-End Training
Later in the paper (and adopted as standard in modern implementations):
- Both RPN and Fast R-CNN losses are merged into one joint loss:
  $$L_{total} = L_{RPN} + L_{FastRCNN}$$
- Backpropagation updates all layers in a single forward/backward pass.
- In **Approximate Joint Training**, gradients with respect to the predicted proposal coordinates flowing through RoI Pooling are ignored. The authors showed empirically that this approximation has negligible impact on final accuracy while reducing training time by 25-50%.

## 9. End-to-End Concrete Numerical Walkthrough

Let us trace a single concrete image through the complete Faster R-CNN pipeline with exact numbers:

### Input:
- Image: $800 \times 600$ pixels (RGB, 3 channels).
- Backbone: VGG-16 (13 conv layers + 3 fc layers, downsampling factor $= 16$).

### Stage 1: Backbone Feature Extraction
$$\text{Feature Map Width} = \left\lfloor \frac{800}{16} \right\rfloor = 50$$
$$\text{Feature Map Height} = \left\lfloor \frac{600}{16} \right\rfloor = 37.5 \approx 38$$
$$\text{Output Feature Tensor Shape} = [1, 512, 38, 50]$$

---

### Stage 2: RPN Sliding Window & Predictions
1. **$3 \times 3$ Conv Layer:**
   - Input: $[1, 512, 38, 50]$
   - Kernel: $3 \times 3$, padding $= 1$, 512 filters
   - Output: $[1, 512, 38, 50]$
2. **Anchor Count:**
   - Spatial locations: $38 \times 50 = 1,900$ locations.
   - Anchors per location: $k = 9$ (scales: $128^2, 256^2, 512^2$; ratios: $1:1, 1:2, 2:1$).
   - Total Anchors: $1,900 \times 9 = 17,100$ anchors.
3. **`cls` 1x1 Conv Layer:**
   - Kernel: $1 \times 1$, $2k = 18$ filters.
   - Output shape: $[1, 18, 38, 50] \to [1, 17100, 2]$ (object vs. background).
4. **`reg` 1x1 Conv Layer:**
   - Kernel: $1 \times 1$, $4k = 36$ filters.
   - Output shape: $[1, 36, 38, 50] \to [1, 17100, 4]$ ($(t_x, t_y, t_w, t_h)$ deltas).

---

### Stage 3: Proposal Filtering
1. **Decode:** All 17,100 anchors are shifted and scaled by their $(t_x, t_y, t_w, t_h)$ to generate candidate bounding boxes.
2. **Clip:** Boxes are clipped to $[0, 800]$ in X and $[0, 600]$ in Y.
3. **Sort:** Boxes are sorted by their positive `cls` probability.
4. **Pre-NMS filter:** Top 6,000 boxes kept.
5. **NMS (IoU = 0.7):** Overlapping duplicate boxes are suppressed.
6. **Post-NMS selection:** Top **300 proposals** are retained!

---

### Stage 4: Fast R-CNN Detection Head
1. **RoI Pooling:**
   - Input: Shared feature map $[1, 512, 38, 50]$ and the 300 proposals.
   - Each proposal coordinates are mapped to feature space (divided by 16).
   - RoI max pooling extracts a fixed $7 \times 7$ feature patch for each proposal.
   - Output shape: $[300, 512, 7, 7]$.
2. **Fully Connected Layers:**
   - Flatten to $512 \times 7 \times 7 = 25,088$.
   - Pass through `fc6` (4096-d) + ReLU + Dropout.
   - Pass through `fc7` (4096-d) + ReLU + Dropout.
3. **Classification & Regression Output:**
   - For PASCAL VOC (20 object classes + 1 background = 21 classes):
   - **Softmax `cls` layer:** $[300, 21]$ class probabilities.
   - **Bounding box `reg` layer:** $[300, 21 \times 4] = [300, 84]$ class-specific coordinate adjustments.
4. **Final NMS:**
   - For each class independently, suppress boxes with $\text{IoU} \ge 0.3$.
   - Output final detected objects with bounding boxes and confidence scores!

## 10. Experimental Results & Key Takeaways

### 10.1 Speed & Latency Comparison
Testing on an NVIDIA K40 GPU (VGG-16 backbone):

| Method | Proposal Mechanism | Proposal Time | Detection Time | Total Time per Image | Frame Rate (fps) | Speedup vs R-CNN |
| :--- | :--- | :---: | :---: | :---: | :---: | :---: |
| **R-CNN** | Selective Search | 2.00 s | 47.00 s | **49.00 s** | 0.02 fps | $1\times$ (Baseline) |
| **Fast R-CNN** | Selective Search | 2.00 s | 0.32 s | **2.32 s** | 0.43 fps | $21\times$ |
| **Faster R-CNN (ZF Net)** | RPN (Shared) | **0.01 s** | 0.05 s | **0.06 s** | **17.0 fps** | **$816\times$** |

> **Key takeaway:** RPN requires only **10 milliseconds**! Faster R-CNN runs **10x faster than Fast R-CNN** and **250x faster than R-CNN** while using the same VGG-16 backbone.

### 10.2 Detection Accuracy on PASCAL VOC & MS COCO
Mean Average Precision (mAP) on PASCAL VOC 2007 test set:

| Method | Backbone | Proposals | Number of Proposals | VOC 2007 mAP (%) |
| :--- | :--- | :--- | :---: | :---: |

| Faster R-CNN | ZF Net | RPN (Shared) | 300 | 59.9% |

> Faster R-CNN with only **300 proposals** achieved **69.9% mAP**, outperforming Fast R-CNN with 2,000 proposals (**66.9%**).

---

### 10.3 Ablation Studies (Anchors, Scales, Sharing)

#### 1. Sharing vs. Not Sharing Features
- When RPN and Fast R-CNN were trained separately without sharing features, VOC 2007 mAP dropped from **69.9%** to **68.5%**, and total test time increased from 0.20s to 0.34s.
- Feature sharing improves both **accuracy** and **computational efficiency**.

#### 2. Number of Proposals Evaluation
The authors evaluated mAP on VOC 2007 when varying the number of proposals fed to Fast R-CNN at test time:
- **300 proposals:** 69.9% mAP
- **1,000 proposals:** 70.1% mAP
- **2,000 proposals:** 69.9% mAP
- **100 proposals:** 65.8% mAP

Notice that accuracy plateaus at ~300 proposals! Because RPN's proposals are ranked by a learned neural network, the top 300 are of far higher quality than 2,000 unsupervised Selective Search boxes.

#### 3. Anchor Scales and Aspect Ratios
Testing configurations of scales and aspect ratios:
- 1 scale, 1 ratio: 65.8% mAP
- 3 scales, 1 ratio: 68.8% mAP
- 1 scale, 3 ratios: 67.4% mAP
- **3 scales, 3 ratios (9 anchors):** **69.9% mAP**
Using both diverse scales and aspect ratios is essential for robust multi-scale detection.

## 11. Comprehensive Glossary of Terms

Every technical term used in Faster R-CNN explained with complete clarity:

- **Region Proposal:** A candidate bounding box predicted to likely contain an object of interest, filtering out vast expanses of empty background before detailed classification.
- **Selective Search (SS):** A classical greedy clustering algorithm that merges over-segmented image regions based on color, texture, and size heuristics to create proposals on CPU.
- **Region Proposal Network (RPN):** A fully convolutional sub-network that processes a feature map to predict candidate object bounding boxes and objectness scores simultaneously.
- **Anchor Box:** A fixed-size reference bounding box located at a sliding window center on the feature map, parameterized by scale and aspect ratio.
- **Scale:** The overall area or pixel dimensions of an anchor (e.g., $128^2, 256^2, 512^2$).
- **Aspect Ratio:** The ratio of width to height ($w/h$) of an anchor box (e.g., $1:1$ square, $1:2$ vertical/tall, $2:1$ horizontal/wide).
- **Objectness:** A binary classification score measuring whether a candidate box belongs to an object category of interest versus background, regardless of specific class identity.
- **Feature Stride:** The ratio between the spatial dimensions of the input image and the output feature map (e.g., in VGG-16, stride $= 16$, meaning 16 input pixels equal 1 feature pixel).
- **Receptive Field:** The region of the original input image that contributes to a specific neuron's activation in a feature map.
- **Intersection over Union (IoU / Jaccard Index):** The ratio of the area of overlap between two bounding boxes to their combined area of union:
  $$\text{IoU} = \frac{\text{Area}(A \cap B)}{\text{Area}(A \cup B)}$$
- **Non-Maximum Suppression (NMS):** An algorithm that eliminates redundant, overlapping bounding boxes by iteratively selecting the highest-scoring box and discarding any neighboring boxes that have an IoU exceeding a threshold (e.g., 0.7 for RPN, 0.3 for detection).
- **Smooth L1 Loss:** A robust loss function that is quadratic for small errors ($|x| < 1$) and linear for large errors ($|x| \ge 1$), preventing gradient explosion from outlier ground-truth boxes.
- **Bounding Box Regression:** The task of predicting 4 numerical transformations $(t_x, t_y, t_w, t_h)$ to shift and scale an anchor box to tightly fit the true object boundaries.
- **RoI Pooling (Region of Interest Pooling):** A standard max-pooling layer that converts non-uniform region proposals into fixed-size feature maps (e.g., $7 \times 7$) for subsequent fully connected layers.
- **Translation Invariance:** A system property ensuring that if an object moves spatially within the input image, its corresponding representations and predictions move by the exact same amount.
- **Mean Average Precision (mAP):** The standard performance metric for object detection, calculated as the mean of the Average Precision (area under the Precision-Recall curve) across all classes.
- **4-Step Alternating Training:** The optimization procedure where RPN and Fast R-CNN are trained alternately with frozen shared convolutional layers to achieve unified shared representations.
- **Approximate Joint Training:** A unified end-to-end training procedure combining RPN loss and Fast R-CNN loss in a single forward/backward pass, ignoring the derivatives of RoI coordinates.
